# 학급 디지털 게시판 기획서 v0.2

작성일: 2026-11-08 / 저장소: `176-oss/class`, 새 폴더 `board/`
상태: 검토 반영본 (v0.1 검토 결과 반영 + 이미지, 청소당번, 디자인 편집 추가)

## 1. 한 줄 요약
교무실 PC에서 안내, 시간표, 일정, 청소당번, 이미지를 입력하면 학급 PC 바탕에 전체화면 게시판으로 뜬다. 학급 PC는 로그인하지 않는다. 학급 PC는 크롬/엣지 앱 모드 바로가기로 열고 PC를 켜면 자동 실행된다.

## 2. 사용자 결정 (2026-11-08)
- 교무실 PC에서 입력, 학급 PC에는 로그인 없이 표시 (위젯처럼)
- 학급 PC 표시: 전체화면 웹페이지, 주소창 없는 앱 모드 바로가기 + 시작프로그램 자동 실행 (exe는 만들지 않음. 필요하면 나중에 같은 화면을 감싸서 추가)
- 구성: 안내 목록 + 시간표 + 일정 + 청소당번 + 이미지
- 디자인 편집 가능: 첫 버전은 템플릿 방식, 자유 배치 편집기는 2단계
- 다른 선생님도 쓸 수 있게 한다 (선생님마다 자기 구글 계정, 자기 게시판)
- 청소당번의 이름 표시 방식은 사용자 선택 대기 중 (기본값: 번호만)

## 3. 구조
```
[교무실 PC] board/admin.html  --구글 로그인-->  구글 드라이브 board-<무작위>.json, img-<무작위>.jpg (링크가 있는 사람 읽기 전용)
[학급 PC ] board/index.html?f=파일ID  --로그인 없음-->  Drive API(공개 키)로 읽기
```
- 로그인 없이 읽어야 하므로 앱 전용 폴더(appDataFolder)가 아니라 일반 드라이브에 게시판 파일을 만들고 '링크가 있는 모든 사용자 - 뷰어'로 공유한다. Apps Script 방식과 달리 선생님마다 스크립트를 배포할 필요가 없다.
- 범위(scope): `https://www.googleapis.com/auth/drive.file` 하나.
- 읽기: 매분 `files.get?fields=version,modifiedTime`(수백 바이트)만 확인하고, version이 바뀔 때만 `alt=media`로 본문을 받는다. 모든 fetch는 `cache: 'no-store'`.
- 공유 생성은 `{type:'anyone', role:'reader', allowFileDiscovery:false}`만 쓴다. 만든 직후 `permissions.list`로 확인하고, 확인되기 전에는 '만들기 완료'로 처리하지 않는다. 공유가 403으로 막히면 '이 계정은 링크 공유가 허용되지 않습니다. 개인 구글 계정으로 로그인하세요'를 표시한다.
- 서버 없음, 빌드 도구 없음. GitHub Pages 정적 파일(HTML, CSS, ES 모듈).
- 이력(되돌리기용 이전 5개 버전)은 **공유하지 않는다**. appDataFolder에 비공개로 둔다.
- 파일 이름에는 반 이름을 쓰지 않는다. `board-<무작위12자>.json`, 반 이름은 JSON 안 `title`에만.

## 4. 착수 전 스파이크 (개발 1순위, 이 결과가 나쁘면 구조를 바꾼다)
실제 선생님 계정(학교 계정과 개인 계정 모두)으로 아래를 시험하고 결과를 `board/docs/spike.md`에 적는다.
1. `drive.file`로 파일 생성 후 `permissions.create`(anyone/reader/allowFileDiscovery false) 성공 여부
2. 로그인 없는 시크릿 창에서 `fetch(...?alt=media&key=...)` 성공 여부, 오류 응답(403/404) 본문 읽기 가능 여부, 응답 Content-Type
3. 수정 직후 읽기 반영 지연: 10회 측정하여 최대값 기록 (목표 60초 이하)
4. 이미지 파일을 `fetch`해 blob으로 쓰는 방식과 `<img src>` 직접 방식 중 되는 것
5. 같은 키로 PC 여러 대가 1분 간격으로 읽을 때 한도 오류가 나는지 (10분 이상)
6. `files.update`의 조건부 쓰기(If-Match) 지원 여부 (미지원이면 `rev` 방식, 9절)
7. 참조(referrer) 제한이 앱 모드와 fetch에서 동작하는지 (출처 단위 `https://176-oss.github.io/*`)
8. 학교 워크스페이스 계정에서 공유가 막히는지
스파이크가 실패하면 대안(Apps Script 웹앱, 별도 공개 호스팅)을 사용자에게 제시하고 멈춘다.

## 5. 보안과 개인정보
- 게시판 파일과 이미지는 링크를 아는 사람이면 누구나 읽는다. 학생 이름, 연락처, 얼굴 사진, 성적은 올리지 않는 것이 원칙이다. 입력 화면 상단에 상시 안내하고, 이미지 올릴 때와 청소당번 이름 표시를 켤 때 경고를 띄운다. 전화번호 형식(예: 010-0000-0000)은 오탐이 적으므로 저장 시 경고한다.
- 입력 화면에 [지금 공유 끊기]를 가장 눈에 띄는 위치에 둔다 (permissions.delete). 현재 상태 '공유 중 / 중지됨'을 항상 표시한다.
- [게시판 삭제]는 `files.delete`(영구 삭제, 휴지통 이동 금지)로 본 파일, 이미지 파일, 이력을 모두 지운다.
- 표시와 입력 모두 innerHTML 금지, 모든 글은 textContent. 서식은 줄바꿈과 굵게(`strong` 노드)만. 링크와 `a` 태그는 만들지 않는다.
- 외부 코드, CDN, 외부 글꼴 주소 금지. 글꼴(IBM Plex Sans KR)은 `board/fonts/`에 넣고 라이선스(SIL OFL) 파일을 함께 둔다. 예외는 입력 화면의 구글 로그인 스크립트뿐이고, 표시 화면에는 외부 스크립트가 없다.
- 파일 ID(`f`)는 `/^[A-Za-z0-9_-]{20,80}$/`와 일치할 때만 쓰고 `encodeURIComponent`를 적용한다.
- 스키마 상한: 활성 안내 50개, 제목 40자, 본문 500자, 일정 200개, 시간표 요일당 12교시, 청소 구역 12개, 이미지 20개, JSON 200KB. 미지의 필드는 무시, `kind`와 `schemaVersion` 검사. 상한 초과나 검사 실패면 마지막 정상 내용을 유지한다. `schemaVersion`이 표시 화면보다 높으면 알려진 필드만 쓰고, 해석 불가 메이저면 마지막 정상 내용 유지 + 구석에 '화면 업데이트 필요'.
- 공개 API 키는 OAuth 클라이언트와 **다른 Cloud 프로젝트**에서 발급한다. 제한: HTTP 참조 `https://176-oss.github.io/*`(경로로 좁히지 않음), API는 Drive API만. 참조 제한은 위조 가능하므로 보호가 아니라 오용 억제로 설명한다. 남용되면 키를 폐기하고 `config.js`를 바꿔 재배포한다. 표시 화면에 `no-referrer` 정책을 쓰지 않는다.
- 같은 출처(176-oss.github.io)의 다른 앱 저장소와 섞이지 않게 모든 localStorage/IndexedDB/Cache 키는 `classboard:` 접두사 + 파일 ID. `board/` 밖 파일은 수정하지 않고 다른 폴더 코드는 import하지 않고 복사해 고쳐 쓴다 (textgenerator-v2 수정지시서 0-2의 1번과 같은 규칙). 장기적으로 게시판을 별도 주소로 분리하는 안은 선택지로 남긴다.
- OAuth 클라이언트 ID는 바꾸지 않는다 (`drive.file`은 클라이언트 ID 단위라 바꾸면 기존 게시판 파일을 잃는다). 동의 화면이 '테스트' 상태이면 다른 선생님이 못 쓰므로 게시 상태를 확인한다.

## 6. 데이터 (`board-<무작위12자>.json`)
```js
{
  kind: 'class-board', schemaVersion: 1, rev: 12, updatedAt: '2026-11-08T19:30:00+09:00',
  title: '3학년 5반',
  design: {
    template: 'basic', palette: 'honey', fontScale: 1.0,
    layout: { timetable: 'left', blocks: { timetable: true, notices: true, events: true, duty: true }, order: ['notices','events','duty'] },
    background: { kind: 'color', imageId: null, overlay: 0.85 },
    rotateSec: 15, showClock: true
  },
  timetable: [{                       // 시간표 버전 배열 (첫 버전 UI는 1개만)
    effectiveFrom: '2026-09-01',
    periods: [{ no: 1, start: '09:00', end: '09:45', kind: 'class' }, { no: 5, start: '12:30', end: '13:20', kind: 'break', label: '점심' }],
    week: { mon: [{ period: 1, subject: '국어', note: '' }], tue: [], wed: [], thu: [], fri: [] },
    periodsByDay: { wed: [ /* 요일별 교시표가 다를 때만 */ ] },
    overrides: [{ date: '2026-11-12', replaceAll: false, items: [{ period: 3, subject: '체육', note: '강당' }] }]  // subject '' = 해당 교시 없음
  }],
  noClass: [{ startDate: '2026-12-24', endDate: '2027-02-28', label: '겨울방학' }],
  events: [{ id, date: '2026-11-20', endDate: null, time: '', title: '현장체험학습', note: '' }],
  notices: [{ id, title, body, important: false, startDate, endDate: null, order, imageId: null, imageAlt: '' }],
  images: [{ id, fileId, alt, w, h }],
  duty: {
    zones: [{ id, name: '교실 청소' }, { id, name: '복도' }],
    students: [{ no: 1 }, { no: 2 }],            // 기본(번호만). 이름은 아래 표시 방식을 켠 경우에만 name이 들어간다
    nameMode: 'number',                          // 'number' | 'masked' | 'full'
    mode: 'rotate',                              // 'rotate' | 'fixed'
    rotate: { startDate: '2026-11-09', unit: 'week', perZone: 3 },
    fixed: { mon: { zoneId: [no, no] } },
    note: ''
  }
}
```
- 안내는 `startDate`~`endDate`에만 보인다. `endDate`가 null이면 상시. 종료 후 90일이 지나면 삭제를 권하고, 파일이 150KB를 넘으면 경고한다.
- 날짜와 시각 계산은 PC 시간대 설정에 의존하지 않고 `Intl.DateTimeFormat`의 `timeZone:'Asia/Seoul'`로 한다. 날짜 비교는 'YYYY-MM-DD' 문자열로.
- 교시 시간 저장 시 `HH:MM` 형식, start<end, 다음 교시 start>=이전 end를 검사하고 위반이면 저장을 막는다.
- 시간표 `overrides`는 교시 단위 병합이다. `replaceAll:true`면 그날 전체 교체. `subject:''`는 그 교시 없음.
- 격주·A/B주 시간표는 첫 버전에서 제외한다.
- 공휴일은 선생님이 `noClass`에 직접 입력한다. 연도별 공휴일 목록을 번들하려면 검증된 출처를 명시하고 매년 갱신한다 (임의 생성 금지).

## 7. 청소당번
- 구역(교실, 복도, 급식실 앞 등)과 학생 번호 목록을 넣으면 요일별(고정) 또는 주/일 단위 순환(rotate)으로 배정한다. 순환은 `startDate` 기준으로 `unit`마다 구역별 `perZone`명씩 번호 순서대로 밀린다. 순수 함수로 만들고 경계(학생 수가 나누어떨어지지 않을 때, 마지막 주, 시작일 이전)를 테스트한다.
- 표시: 오늘 구역별 당번 카드. 번호만 표시가 기본이다 ('3번, 7번, 12번').
- 이름 표시 방식 선택 `nameMode`
  - `number`: 이름은 파일에 들어가지 않는다 (기본, 가장 안전).
  - `masked`: '김○○' 형식. 동명이인 주의 문구.
  - `full`: 전체 이름. 켜면 '링크가 새면 학생 이름이 공개됩니다' 경고와 확인 필요.
- 이름은 번호 대응표를 입력 화면에서만 다루고, `number`일 때는 업로드하지 않는다 (이 PC의 화면 입력에서만 보이고 저장하지 않음).
- 당번 교체(결석 등) 임시 변경: 오늘 하루 [이 번호 빼기/바꾸기].

## 8. 이미지
- 입력 화면에서 JPEG/PNG/WebP를 선택 → 브라우저에서 canvas로 다시 그려 JPEG/WebP로 저장(긴 변 1600px 이하, 약 500KB 이하). 다시 그리기 때문에 EXIF(위치 정보 등)가 제거된다.
- 드라이브에 `img-<무작위12자>.jpg` 별도 파일로 올리고 같은 방식으로 공유한다. 안내에 붙이거나 배경 이미지로 쓴다. 이미지마다 대체 글(alt) 입력칸을 둔다.
- 안내를 지우면 그 이미지도 영구 삭제. 게시판당 최대 20개.
- 표시 화면은 처음 한 번 받아 Cache Storage에 보관하고(오프라인에서도 표시), 안 쓰는 이미지는 정리한다.
- 올릴 때 '학생 얼굴이 나온 사진은 올리지 마세요' 경고.

## 9. 입력 화면 (`board/admin.html`)
- 구글 로그인 → 게시판 목록(여러 반) 또는 [새 게시판 만들기] (공유 성공을 확인한 뒤에만 완료)
- 탭: 안내 / 시간표 / 일정 / 청소당번 / 이미지 / 디자인 / 학급 PC 연결
  - 안내: 제목, 내용, 게시 기간, 중요 표시, 이미지 붙이기, 위로·아래로(드래그 없음), 복제, 지난 안내
  - 시간표: 요일×교시 표, 교시 시간(쉬는·점심 구분), 특정 날짜 변경, 방학·휴업일(`noClass`)
  - 일정, 청소당번, 이미지: 위 설명대로
  - 디자인(10절)
  - 학급 PC 연결: 표시 주소, [주소 복사], 설치 방법(11절), [표시 화면 미리보기], 공유 상태와 [지금 공유 끊기], [게시판 삭제]
- 오른쪽에 학급 PC 모양 실시간 미리보기 (저장 전 내용)
- [저장]: 저장 직전 `files.get?fields=version`을 비교한다. 다르면 멈추고 [서버 내용 불러오기] / [내 내용으로 덮어쓰기] / [차이 보기] 중 고르게 한다. 파일에 단조 증가 `rev`를 기록한다. 동시 수정은 완전히 막을 수 없고 마지막 저장이 이긴다고 안내한다. 끝나면 '학급 PC에는 1분 안에 반영됩니다'.
- 저장 안 한 변경이 있으면 닫을 때 경고. 이전 5개 버전은 appDataFolder에 비공개 보관하고 [이전으로 되돌리기] 제공.
- 상단 상시 안내: '이름·연락처 같은 개인정보는 쓰지 마세요. 링크를 아는 사람은 누구나 볼 수 있습니다.'
- 같은 게시판을 여러 선생님이 함께 수정하는 기능은 첫 버전 제외. 교사 전근 시 인수인계(파일 소유자 이전) 방법을 안내서에 한 문단 적는다.

## 10. 디자인 편집 (첫 버전: 템플릿 방식)
- 편집 항목
  - 색 묶음(palette): 기존 앱과 같은 계열 4가지 이내 (꿀색 기본, 짙은 갈색, 연한 모래, 짙은 바탕). 모든 묶음은 글자 대비 4.5:1 이상을 코드에서 검사한다.
  - 글자 크기(`fontScale` 0.8~1.4)
  - 구성: 시간표 위치(왼쪽/오른쪽), 칸 켜기/끄기(시간표, 안내, 일정, 청소당번), 칸 순서(위로·아래로)
  - 배경: 단색 또는 이미지(어둡게/밝게 덮개 `overlay`)
  - 안내 페이지 전환 시간, 시계 표시
- 글꼴은 IBM Plex Sans KR 하나로 고정한다 (선택지 없음).
- 편집은 오른쪽 미리보기에 즉시 반영되고, [기본값으로 되돌리기]를 둔다.
- 2단계(별도 요청 시): 칸을 끌어서 자유 배치, 크기 조절. 데이터는 `design.layout.free`로 확장 가능하게 `schemaVersion`을 관리한다.

## 11. 학급 PC 표시 화면 (`board/index.html?f=파일ID`)
- 16:9 전체화면, 글자는 `vw` 기준으로 크게 (본문 28px 상당 이상)
- 배치 (기본 템플릿): 위 띠(학급 이름, 날짜와 요일, 현재 시각) / 왼쪽 오늘 시간표 / 가운데·오른쪽 안내(이미지 포함) / 아래 일정 / 청소당번 카드
  - 시간표: 지금 교시는 진행색 강조, 지난 교시는 흐리게, 교시 사이에는 직전 교시를 흐리게 하고 다음 교시에 '다음' 표시. `noClass` 기간과 주말은 라벨(예: 겨울방학)만 표시.
  - 안내: 중요 안내는 모든 페이지 상단에 최대 2개까지 고정, 나머지는 중요, `order`, 시작일 순. 페이지 전환 시간은 `max(rotateSec, 글자수/8)`초.
  - 일정: 기간 일정은 진행 중이면 'D-Day', 시작 전이면 D-n, 끝나면 숨김.
- 갱신: 시작 때 0~60초 무작위 지연 후 한 번, 이후 60초마다 version 확인. 오늘 날짜 기준 계산(시간표, 안내, D-day, 당번)은 캐시된 원본에서 매번 새로 한다.
- 실패 대응: 403 `rateLimitExceeded`/`userRateLimitExceeded`/`downloadQuotaExceeded`는 지수 백오프(1, 2, 5, 최대 10분)하고 마지막 정상 내용을 유지한다. 10분 넘게 갱신 못 하면 구석에 '마지막 갱신 14:05'(경고색), 24시간 넘으면 '며칠째 갱신되지 않음'. 화면을 가리는 오류 창은 없다.
- 오프라인 시작: **서비스 워커**가 index.html, JS, CSS, 글꼴, 마지막 데이터와 이미지를 캐시해, 네트워크 없이 부팅해도 마지막 내용으로 열린다. 캐시와 데이터가 모두 비어 있어도 '연결 중'을 표시하고 30초, 60초, 5분 간격으로 재시도한다. '주소 오류'는 파일 ID 형식 불량이나 404일 때만. 서비스 워커는 새 배포가 24시간 안에 반영되게 버전을 갱신한다.
- 하루 한 번 새벽 재로드는 같은 출처 파일 1개를 먼저 fetch해 성공했을 때만 실행한다.
- 시계 점검: 파일 `updatedAt`이 PC 현재 시각보다 5분 넘게 미래이면 구석에 '이 PC의 시계를 확인하세요'를 작게 표시한다. 서버 시각 헤더에 의존하지 않는다.
- 마우스 커서는 3초 움직임이 없으면 숨김. Wake Lock을 시도하고 `visibilitychange`에서 다시 요청, 거부되어도 오류 없이 넘어간다.
- 개발용 '가짜 드라이브 모드'(localhost에서는 키가 거부됨)를 둔다.

## 12. 학급 PC 설치
**기본 경로는 수동 설치, `.bat`은 보조.** 학교 PC에서 내려받은 `.bat`이나 PowerShell이 막힐 수 있다.
- 입력 화면의 '학급 PC 연결'에서 바로가기 대상 명령줄 전체를 [복사]로 제공한다.
  `"크롬 경로" --app=표시주소 --start-fullscreen --user-data-dir=%LOCALAPPDATA%\ClassBoard --hide-crash-restore-bubble`
  - 전용 프로필(`--user-data-dir`)로 다른 앱 저장소와 분리하고, 이미 열려 있는 크롬에 붙어 옵션이 무시되는 문제를 줄인다.
  - 비정상 종료 후 복원 말풍선: `--hide-crash-restore-bubble`, 안 되면 `--disable-session-crashed-bubble`을 시험한다.
  - 엣지는 `msedge.exe`로 같은 방식 (옵션 동작은 확인 필요).
- 수동 순서: Win+R → `shell:startup` → 바로가기 만들기 → 대상에 위 명령줄 붙여넣기. 지연 실행을 위해 20~30초 지연 안내(네트워크가 붙은 뒤 열리도록).
- `ClassBoard-설치.bat`(브라우저에서 주소를 넣어 생성): 크롬을 `App Paths` 레지스트리, `Program Files`, `Program Files (x86)`, `%LOCALAPPDATA%` 순으로 찾고, 없으면 엣지. 시작프로그램과 바탕화면에 `ClassBoard.lnk` 생성, 생성 후 파일 존재 확인, 실패하면 '수동 설치 방법을 따르세요'와 이유 표시. 시작 지연 포함. `ClassBoard-제거.bat` 제공. 파일 이름 영문, 내용 UTF-8(`chcp 65001`).
- 종료는 Alt+F4. 학생이 만질 수 있는 PC는 `--kiosk` 사용 또는 학생 손이 닿지 않게 두도록 안내하고, 종료 방법을 반드시 같이 적는다.
- 설치 안내서에 포함: 전원 옵션(화면 끄기·절전 안 함), '설정 > 시간 및 언어 > 지금 동기화', 자동 로그인 여부, 재시작 시 초기화되는 프로그램(복원) 사용 시 전용 프로필 폴더와 바로가기를 예외로 두는 방법.

## 16. 완료 기준 (검증 방법 포함)
1. 반영 시간: 저장 후 로그인 없는 시크릿 창에서 반영까지 10회 측정, 최대 60초 이하 (결과를 review.md에 기록)
2. 오프라인: (a) 연 채로 네트워크를 끊고 10분 뒤 '마지막 갱신' 표시, (b) 네트워크 끈 채 브라우저 재시작해도 마지막 내용이 열림, (c) 네트워크 없이 부팅 후 연결하면 자동 갱신
3. 설치: 실제 학급 PC 1대와 개인 PC 1대에서, 크롬이 열려 있을 때와 닫혀 있을 때 모두 전체화면으로 열리고 재시작 후 자동 실행, 비정상 종료 후 복원 말풍선 없음
4. 시간 계산 테스트(시간 고정 입력): 자정 직전·직후, 교시 경계 09:44/09:45, 쉬는 시간, 공휴일, 방학, overrides 병합, 안내 시작일=오늘/종료일=어제, PC 시간대가 UTC일 때
5. 청소당번 순환 테스트: 학생 수가 나누어떨어지지 않을 때, 시작일 이전, 주/일 단위, 임시 교체
6. 보안 검색: `src="http`, `href="http`, `import ... from 'http`, `innerHTML`, `insertAdjacentHTML`, `document.write`, `eval` 검색 결과를 review.md에 첨부. `board/` 밖 변경 0개(`git diff --stat`)
7. 공유 중지·삭제 후 로그인 없는 브라우저에서 파일과 이미지가 열리지 않음. 이력 파일이 공유되지 않음(`permissions.list` 확인)
8. `f` 파라미터에 이상한 값을 넣어도 API 호출이 나가지 않음
9. 학교 워크스페이스 계정에서 공유가 막히면 안내 문구가 나옴
10. 표시 화면이 1280x720, 1366x768, 1920x1080에서 최악 데이터(안내 50개, 제목 40자, 본문 500자, 시간표 10교시, 일정 20개, 구역 12개)로 글자가 잘리지 않음 (스크린샷 3장)
11. 이미지: 업로드 후 EXIF 제거, 500KB 이하, 안내 삭제 시 이미지 영구 삭제, 오프라인에서도 표시
12. 디자인: 모든 색 묶음에서 대비 4.5:1 이상, 칸 끄기와 순서 변경이 표시 화면에 반영
13. 서비스 워커 갱신 후 새 배포가 24시간 안에 학급 PC에 반영
