# 스파이크 결과 (기획서 4절)

상태: **시험 대기** (시험 페이지 준비됨, 결과 없음)
시험 페이지: `spike/index.html` → 배포 주소 `https://176-oss.github.io/class-board/spike/`

## 선생님이 할 일 (순서대로)

준비 (한 번)
1. 구글 클라우드 콘솔, 기존 OAuth 클라이언트(앱들과 같은 ID)의 동의 화면에 범위 `.../auth/drive.file`을 추가합니다. 클라이언트 ID는 바꾸지 않습니다. 승인된 자바스크립트 출처에 `https://176-oss.github.io`가 있는지 확인합니다 (기존 앱과 같은 출처라 이미 있을 것입니다).
2. **다른 Cloud 프로젝트**에서 API 키를 만듭니다. 애플리케이션 제한: HTTP 리퍼러 `https://176-oss.github.io/*`. API 제한: Google Drive API만. 그 프로젝트에서 Drive API를 사용 설정합니다.
3. 시험 페이지가 GitHub Pages에 올라가 있어야 합니다 (키의 참조 제한 때문에 localhost에서는 읽기 시험이 403으로 막힙니다). 저장소 설정 > Pages에서 배포 브랜치를 `feat/board-spike`로 잠시 맞추고, 시험이 끝나면 되돌립니다.

시험 A: 개인 gmail 계정 (모두 같은 PC에서)
1. 일반 크롬 창(선생님 창)으로 시험 페이지를 엽니다. API 키를 입력칸에 넣고 [키 저장].
2. [구글 로그인] → 개인 계정 → 허용.
3. [1·8 공유 시험]. 결과에 `1 파일 만들기 통과`, `1·8 공유 통과`가 나오는지 봅니다.
4. [4 시험 이미지 만들기].
5. [주소 복사]로 학급 PC 창 주소를 복사합니다.
6. **시크릿 창**을 열고 그 주소를 붙여 넣습니다. 키를 다시 넣고 [키 저장].
7. 시크릿 창에서 [2·7 읽기 시험], [4 이미지 시험]. 이미지 두 칸이 보이는지 눈으로도 확인합니다.
8. 시크릿 창에서 [3 반영 지연 측정 시작] → 선생님 창에서 [3 반영 지연: 75초마다 10회 수정]. 약 13분 기다립니다. 시크릿 창에 `3 반영 지연 결과`가 나오면 끝입니다.
9. 시크릿 창에서 [5 매분 확인]을 누르고 **10분 이상** 둡니다. 그동안 선생님 창에서 [지금 1회 수정]을 두세 번 누릅니다. 다른 PC나 휴대폰에서도 같은 주소로 [5 매분 확인]을 켜 두면 더 좋습니다.
10. 시크릿 창 [측정 멈춤] → 선생님 창 [6 If-Match 시험].
11. 앱 모드 창 시험(7번): Win+R에 아래를 붙여 넣습니다 (주소는 5번에서 복사한 것으로 바꿈). 열린 창 위쪽 '창 종류'가 '앱 모드'로 나오는지 보고 키를 넣은 뒤 [2·7 읽기 시험], [4 이미지 시험].
    `chrome --app="복사한 주소" --user-data-dir=%TEMP%\ClassBoardSpike`
12. 선생님 창 [공유 끊기] → 시크릿 창 [2·7 읽기 시험]을 다시 눌러 `2 본문 읽기`가 막히는지 봅니다.
13. 각 창의 [결과 전체 복사]를 눌러 대화창에 붙여 넣어 주세요 (선생님 창, 시크릿 창, 앱 모드 창, 다른 PC가 있다면 그것까지).
14. 선생님 창 [시험 파일 모두 삭제].

시험 B: 학교 워크스페이스 계정 (8번)
1. 선생님 창을 새로고침하고 [구글 로그인] → 학교 계정.
2. [1·8 공유 시험]. 로그인부터 막히면 그 화면 문구를, 공유가 막히면 결과 줄을 복사해 주세요.
3. 공유가 됐다면 시험 A의 5~7번만 다시 해서 로그인 없이 읽히는지 확인하고, [시험 파일 모두 삭제].

적어 줄 것: [결과 전체 복사] 내용, 그리고 눈으로 본 것 (이미지 두 칸이 보였는지, 앱 모드 창이 주소창 없이 열렸는지).

## 시험 페이지가 하는 일

| 번호 | 버튼 | 판정 |
|---|---|---|
| 1 | 1·8 공유 시험 | `board-<무작위12자>.json`(가짜 데이터)을 내 드라이브에 만들고 `permissions.create {anyone, reader, allowFileDiscovery:false}`, 이어서 `permissions.list`에 그 권한이 있으면 통과. 대조용으로 공유하지 않은 파일 하나도 만든다 |
| 2 | 2·7 읽기 시험 | 로그인 없이 `files.get?fields=version,modifiedTime&key=`, `alt=media&key=`. 없는 ID로 404, 공유 안 한 파일로 오류를 받고 본문(JSON)과 Content-Type을 기록 |
| 3 | 3 측정 + 75초마다 10회 수정 | 선생님 창이 `writtenAt`(시각)을 넣어 저장하고, 학급 PC 창이 3초마다 읽어 본문 반영까지 걸린 시간을 잰다. 10회 최대 60초 이하면 통과. 두 창이 같은 PC여야 시계가 같다 |
| 4 | 시험 이미지 만들기 / 4 이미지 시험 | canvas로 그린 가짜 JPEG을 올리고 공유. `fetch`→blob→objectURL 방식과 `<img src=...&key=>` 직접 방식을 각각 표시 |
| 5 | 5 매분 확인 | 표시 화면과 같은 방식(매분 version만, 바뀌면 본문). 5분마다 요청 수와 오류 수 기록. 10분 이상 오류 0이면 통과 |
| 6 | 6 If-Match 시험 | 틀린 `If-Match`로 `files.update`. 412면 지원, 그냥 저장되면 무시(= `rev` 방식), 그 밖은 응답 기록 |
| 7 | 2·7 읽기 시험 (일반·앱 모드 창) | 출처와 창 종류를 기록. 같은 요청을 `referrerPolicy:'no-referrer'`로도 보내 403이 나면 키 참조 제한이 실제로 걸려 있다는 뜻 |
| 8 | 학교 계정으로 1·8 공유 시험 | 로그인 계정 도메인을 기록. 공유가 403이면 기획서의 안내 문구를 함께 출력 |

- 외부 코드: 구글 로그인 스크립트(`accounts.google.com/gsi/client`)만, 로그인할 때 넣는다.
- 저장 키: `classboard:spike:key`(API 키), `classboard:spike:files`(만든 시험 파일 ID). 토큰은 메모리에만.
- 파일 ID는 `/^[A-Za-z0-9_-]{20,80}$/`일 때만 쓰고 `encodeURIComponent`. 형식이 틀리면 요청을 보내지 않는다 (localhost에서 확인함).
- 삭제는 `files.delete`(영구 삭제).

## 저장소 변경 메모 (기획서와 다른 점)

- 게시판은 `176-oss/class`의 `board/` 폴더가 아니라 새 저장소 `176-oss/class-board`의 루트에 둔다 (2026-11-08 선생님 결정). 기획서의 `board/...` 경로는 루트 기준으로 읽는다 (`board/docs/` → `docs/`, `board/index.html` → `index.html`).
