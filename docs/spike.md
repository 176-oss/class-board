# 스파이크 결과 (기획서 4절)

상태: **스파이크 통과 (2026-11-08 21:37)**. 8개 중 7개 통과, 6번(If-Match)은 미지원이지만 기획서에 대안(`rev`)이 있어 구조 변경 없음. 기획서 3절 구조(drive.file + 링크 공유 + 공개 키 읽기)로 본 개발을 시작해도 된다.

본 개발에 넘길 것
- 본문·이미지는 `https://www.googleapis.com/download/drive/v3/files/{id}?alt=media&key=` 로 읽는다 (`/drive/v3/files/{id}?alt=media`는 구글 자동 요청 차단 페이지가 CORS 없이 와서 fetch 실패).
- 로그인 토큰을 붙여 읽을 때(입력 화면)는 반대로 기본 주소 `/drive/v3/files/{id}?alt=media`를 쓴다. 다운로드 주소는 `Authorization` 헤더의 사전 확인(OPTIONS)에 503을 돌려줘 브라우저가 막는다 (2026-11-09, 배포 후 입력 화면에서 발견).
- 동시 저장은 `rev` + 저장 직전 `files.get?fields=version` 비교 (If-Match 무시됨, 응답 ETag 헤더도 안 보임).
- 가려진 탭은 타이머가 1분 단위로 늦춰진다. 표시 화면의 매분 확인이 최대 약 1분 더 늦을 수 있고, 학급 PC는 전체화면이라 보통은 해당 없음. 필요하면 워커 타이머.
- 키 참조 제한은 `Referer` 또는 `Origin`으로 통과한다. 둘 다 없는 요청만 막힌다. 표시 화면에 `no-referrer` 정책을 쓰지 않는다는 기획서 5절 규칙은 `<img>` 때문에 그대로 필요.
- 미확인으로 남은 것: 학급 PC 여러 대 동시 매분 확인(5번은 1대 기준), 다른 학교 도메인(관리자 설정에 따라 다를 수 있음), 엣지 앱 모드.
시험 페이지: `spike/index.html` → 배포 주소 `https://176-oss.github.io/class-board/spike/`

## 시험 중 발견 (2026-11-08)

- 2번 1차: 로그인 없이 `files.get?fields=version`은 200. `drive/v3/files/{id}?alt=media`는 6~9초 뒤 `Failed to fetch`. 같은 주소를 curl로 보면 403 `text/html` 구글 'Sorry... automated queries' 페이지이고 CORS 헤더가 없다 (가짜 키, 없는 ID, 키 없음 모두 같음). 다운로드 전용 주소 `https://www.googleapis.com/download/drive/v3/files/{id}?alt=media&key=`는 JSON 오류와 `Access-Control-Allow-Origin: https://176-oss.github.io`를 정상으로 돌려준다. 시험 페이지의 본문·이미지 읽기를 이 주소로 바꿨다. 본 개발도 본문은 이 주소를 쓴다.
- 7번 1차 (20:31): `referrerPolicy:'no-referrer'`로 보낸 `files.get?fields=version`이 200. 키에 웹사이트(HTTP 리퍼러) 제한이 아직 걸려 있지 않다. 키 설정 확인 뒤 다시 시험.
- 3번 1차 (20:48, Claude가 크롬 연결로 실행): 1~2회 3초·4초, 3~6회 15·60·45·30초. 75초 수정과 60초 확인이 엇갈린 무늬라, 가려진 탭의 타이머를 크롬이 1분 단위로 늦춘 탓으로 판단해 무효 처리. 측정 타이머를 워커로 옮겨(버전 5) 다시 잰다. 표시 화면도 같은 영향을 받으므로 본 개발에서 매분 확인 타이머의 지연을 고려한다 (최대 약 1분 추가).
